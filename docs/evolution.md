# 自我改进与模型升级

状态：设计目标，未实现自动改进。

## 三类改进

1. 研究对象改进：例如项目中的算法或模型。
2. 研究系统改进：例如上下文整理、实验规划、恢复策略。
3. 改进机制改进：例如候选产生、筛选和经验整理方法。

外部模型升级独立记录，不自动归因于 researchOS 的自我改进。第一版优先实现可靠任务循环，再研究第二、第三类。

## 候选生命周期

提出候选 → 隔离分支/环境 → 固定协议比较 → 保存结果 → 根据采用标准推广或保留/拒绝。

候选包含 parent_id、修改内容、预期收益、范围、成本及证据。保留有价值的历史分支，采用受存储/算力预算约束的归档策略，不要求无限保留全部产物。

正在评估的候选不能修改该次比较的评分器、保留任务和历史证据。评价方法的新版本是独立变更；新旧策略须在同一新版本下重新比较。

## 如何验证变强

- 比较质量、证据可靠性、成本、延迟和人类介入，保留各项结果，避免只看单一分数。
- 固定模型与预算评估流程收益；更换模型另开比较，必要时交叉评估模型和策略。
- 在开发任务上优化，在未参与优化的任务上验证。保留任务反馈不回流成逐题训练材料；长期使用需轮换任务集。
- 多次运行并扰动任务顺序，报告样本量、波动和失败例。
- 用可执行评价及原始产物核实；模型裁判辅助评估定性部分，不能凭文风认定科学结果成立。
- 定义采用门槛和回退条件，禁止把偶然单次提升宣称为持续递归增长。

## 经验记录

经验包含内容、来源任务、支持与反例、适用环境/模型/策略、置信依据、更新时间和失效条件。项目经验与跨项目经验分开，只有验证迁移后才提升为通用经验。

采用增量更新，允许反驳和废弃；原始证据不随摘要更新消失。经验数量增长不代表能力提高。

## 留给未来模型的空间

稳定的是任务、证据与操作协议。规划步骤、Agent 分工、工具实现与模型可替换。新模型可以重新解释旧结果，旧决策仍保留。

保存可观察的操作、工具反馈、产物与决策，不依赖不可获取的内部推理。未来如开展训练，另行处理数据许可、脱敏、数据集划分和训练接口；当前不承诺会训练基础模型。

每个项目固定已使用的框架与策略版本。核心升级也通过独立开发与回归验证；元策略不能在运行中自行改变宿主权限或预算上限。
